# Architecture decisions

Status: the project direction below is locked for the synthetic correspondence slice. A future stack decision does not provision a service, enable a model, or authorize live data. The explicit PR1 scope and release gates control executable behavior.

- ADR-001 — Private monorepo. Shared contracts, local skills, schema, adapters, and tests change together. Revisit repository boundaries only through an explicit architecture decision.
- ADR-002 — Google ADK + Gemini + Cloud SQL for PostgreSQL. This is the locked agent/model/database direction. The earlier wording “ADK preferred” and interchangeable n8n/LangGraph or other model-provider alternatives is superseded; those are not baseline options. Narrow interfaces keep deterministic controls independent from a future runtime, not permission to swap or activate a provider. PR1 has no ADK calls, model requests, live provider adapters, cloud deployment, billing, or IAM changes. Local disposable PostgreSQL tests verify database behavior without provisioning Cloud SQL.
- ADR-003 — Deterministic workflow state and policy outside agents. Validate actors, explicit state edges, current matter eligibility, source versions, scope, and exact-action approval before authorized progress. A model or retrieved document cannot grant authority.
- ADR-004 — Authoritative originals remain in existing systems. Clio identifiers are provider signals; internal verified matter UUIDs are distinct. Preserve source references, versions, canonical digests, and immutable resolution evidence. Any future derived live-data copy requires its own authorized retention and access policy.
- ADR-005 — Synthetic local slice precedes integration and deployment. The documentation-only foundation has progressed to local Python controls, an in-memory mock executor, and disposable PostgreSQL migrations/tests. This does not activate the later roadmap phases. Require explicit scope and review before live data, integrations, cloud resources, or production execution.
- ADR-006 — Evidence-bound resolution and continuous eligibility. Freeze trusted synthetic signal evidence at intake; derive resolution from the originating inbox, not a replacement caller argument. Recheck and lock OPEN mappings during progress. Revocation withdraws active scope and quarantines the run while immutable resolution and historical scope references remain intact.
- ADR-007 — Replays preserve one accepted event/run. Canonical matching replays return the existing run. Contradictory signals or payload evidence retain the original inbox, quarantine a nonterminal run, and append an audit anomaly. Terminal runs retain their decision; contradictions do not authorize retry.
- ADR-008 — Isolated transactional audit writes. Application roles cannot forge audit inserts. The restricted `wl_audit_writer` trigger path writes audit in the state transaction, with pinned search paths and schema-qualified relations. Evidence immutability, forced RLS, trigger-source checks, rollback, and concurrent resolution/revocation are verified on a fresh local PostgreSQL16+ cluster.

The current scope is specified in [PR1_SPEC.md](../workflows/incoming-email/PR1_SPEC.md). [AGENTS.md](../AGENTS.md) and [governance](GOVERNANCE.md) retain the managing attorney's authority and the separate release boundary.
